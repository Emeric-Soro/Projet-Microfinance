================================================================================
1. VUE D'ENSEMBLE & ARCHITECTURE
================================================================================

Application de microfinance complete ("Soutra Finance") comportant :
- Un backend API REST (Spring Boot) sur port 8080
- Un frontoffice backoffice (HTML/JS vanilla) sur port 3000
- Un portail client e-banking (HTML/JS vanilla) sur port 3001
- Une base de donnees Oracle XE sur port 1521
- Un outil d'admin DB CloudBeaver sur port 8978

Architecture: Monolite modulaire avec separation Backend/Frontend via API REST.
Authentification: JWT (stateless), 2FA OTP, session guard cote client.
RBAC: Controle cote backend (@PreAuthorize) + cote frontend (sidebar filtering).

================================================================================
2. STACK TECHNOLOGIQUE
================================================================================

BACKEND:
- Java 21 + Spring Boot 3.5.13
- Hibernate/JPA + Flyway (20 migrations SQL)
- JWT (jjwt) — HS256, access tokens (1h) + refresh tokens (7d)
- BCrypt password hashing
- Caffeine (dev) / Redis (prod) — JWT blacklist + tarification cache
- Lombok + MapStruct + Bean Validation
- SpringDoc OpenAPI / Swagger (dev uniquement)
- Multi-stage Docker (Maven 3.9 build, JDK 21 runtime)

BASE DE DONNEES:
- Oracle XE 21 (gvenzl/oracle-xe:21-slim)
- Schema: CORE_BANKING_USER
- Tables prefixées: soutra_*
- 20 scripts Flyway (V0_001 a V20)
- Donnees de reference: roles, statuts, produits, agences

FRONTEND:
- HTML5 / CSS3 / JavaScript vanilla (pas de framework)
- Chart.js (vendored) pour graphiques
- Design system custom (backoffice.css, 1981 lignes)
- Portail client: glassmorphism design (portal.css)

DEPLOYMENT:
- Docker Compose (3 services)
- Wamp64 local dev

4.4 SECURITY ARCHITECTURE
──────────────────────────

JWT Auth Flow:
  1. JwtAuthenticationFilter (OncePerRequestFilter)
     - extracts Bearer token
     - validates signature + expiry + blacklist
     - loads UserDetails
     - sets SecurityContext
  2. JwtService — HS256 signing
     - access tokens (1h default)
     - refresh tokens (7d)
     - JTI claim, token_type claim
  3. JwtTokenBlacklistService
     - in-memory (dev) or Redis (prod)
  4. ApplicationConfig
     - BCryptPasswordEncoder
     - DaoAuthenticationProvider
     - UserDetailsService (from UtilisateurRepository)

Filter Chain:
  1. PublicApiRateLimitingFilter (before JWT filter)
     - Rate limiting for public endpoints
  2. JwtAuthenticationFilter (before UsernamePasswordAuthenticationFilter)

Session Management: STATELESS (no server-side sessions)

CORS: Configurable origins via APP_CORS_ALLOWED_ORIGINS
  - localhost:5173, :80, :3000, :3001 + 127.0.0.1 variants
  - Methods: GET/POST/PUT/DELETE/PATCH/OPTIONS

Public Endpoints:
  - POST /api/v1/auth/login, /api/v1/auth/refresh
  - POST /api/v1/utilisateurs/login, /api/v1/utilisateurs
  - POST /api/v1/mobile/auth/*
  - POST /api/v1/credits/simulation, /api/v1/mobile/credits/simulation
  - POST /api/v1/clients (self-registration)
  - GET  /api/v1/health, /api/v1/health/db, /api/v1/health/cache
  - /upload/** (file serving)
  - /actuator/health/**, /actuator/info

Account Lockout: 5 failed attempts → 15min lockout
OTP: 6-digit code, 5min validity, 3 max attempts
Credentials expiry: 90 days
Password reset: Email token, 30min validity

Cross-cutting:
  - @AuditLog annotation + AuditLogAspect (AOP)
  - @accountAccessSecurity SpEL bean (CLIENT role: own accounts only)
  - @Version on Client, Compte, Credit, Transaction (optimistic locking)
  - File upload: configurable storage, 5MB max
  - SMS: Wave, Orange Money, MTN MoMo (configurable)
  - Email: SMTP (Gmail default), password reset

5.4 LOGIN FLOW
───────────────

  index.html (meta refresh)
      ↓
  login.html
      POST /api/v1/utilisateurs/login
      ↓
  ├─ Si res.otpRequis === false:
  │     SF.setSession(data) → stocke token + user
  │     redirect → getHomeDashboardUrl(user)
  │
  └─ Si res.otpRequis === true:
        SF.setSession(data) → stocke token, user, challengeId
        sessionStorage.setItem('sf_otp_login', login)
        redirect → otp.html
            ↓
        otp.html (6-digit input, 272s countdown)
            POST /api/v1/utilisateurs/login/otp
            (login, challengeId, codeOtp)
            ↓
            ├─ Si ok: SF.setSession(data) → JWT final
            │         clear sf_otp_login + sf_challenge_id
            │         redirect → getHomeDashboardUrl(user)
            │
            └─ Si error: shake animation + toast error
                         retry ou retour login

  Session Guard (guardSession()):
    - Execute immediatement au chargement de chaque page
    - Si pas de sf_token et page pas dans [login, otp, mot-de-passe-oublie]
      → redirect vers login.html

  Token Injection:
    - Chaque appel apiFetch() ajoute Authorization: Bearer
    - Sur reponse 401: clear session + redirect login
